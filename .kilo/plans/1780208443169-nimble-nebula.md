# Plan: Continuous Transfer (Room) Mode

## Overview

Add a room-based continuous transfer mode to the File Delivery Locker. Users can toggle between the existing "locker" mode and the new "room" mode via a switch in the top-right of the page. The room mode uses WebSocket (via Cloudflare Durable Objects) for real-time session management and file sharing.

---

## Architecture

### WebSocket Transport: Durable Objects

Cloudflare Workers natively support WebSocket only through **Durable Objects** (DO). We create a `Room` DO class that:

- Manages WebSocket connections for all clients in a room
- Tracks room state (connected client count, activity timestamp)
- Broadcasts file list changes to all connected clients
- Runs an alarm every 60s to check for idle timeout (30 min with no clients → destroy room + delete all files)
- On destroy, deletes all R2 objects for the room and removes D1 records

### Request Routing

The worker's fetch handler intercepts WebSocket upgrade requests at `/api/rooms/ws?code=ROOM_CODE&password=PASSWORD` and routes them to the `Room` DO. All other requests pass through to the opennext handler.

A custom wrapper script (`scripts/worker-entry.mjs`) provides the fetch handler that wraps opennext's handler with WebSocket routing.

### Data Model (D1)

New tables:

```sql
CREATE TABLE rooms (
  code_hash TEXT PRIMARY KEY,       -- HMAC-SHA256 of room code with pepper
  code TEXT NOT NULL,               -- unhashed 6-char room code (for listing)
  storage_prefix TEXT NOT NULL,     -- R2 key prefix: rooms/ROOM_CODE/
  created_at INTEGER NOT NULL,
  last_activity_at INTEGER NOT NULL -- updated on every WebSocket message
);

CREATE TABLE room_files (
  id TEXT PRIMARY KEY,              -- UUID
  room_code_hash TEXT NOT NULL,     -- FK to rooms.code_hash
  storage_key TEXT NOT NULL,        -- R2 key
  file_name TEXT NOT NULL,
  content_type TEXT NOT NULL,
  delivery_kind TEXT NOT NULL DEFAULT 'file',  -- 'file' | 'text'
  size INTEGER NOT NULL,
  content_hash TEXT,                -- for future dedup
  upload_ip TEXT,
  upload_user_agent TEXT,
  upload_browser TEXT,
  upload_os TEXT,
  upload_device TEXT,
  max_downloads INTEGER NOT NULL DEFAULT 0,     -- 0 = unlimited
  download_count INTEGER NOT NULL DEFAULT 0,
  expires_at INTEGER NOT NULL,                   -- 0 = unlimited
  created_at INTEGER NOT NULL,
  deleted_at INTEGER,
  FOREIGN KEY (room_code_hash) REFERENCES rooms(code_hash)
);

CREATE INDEX idx_room_files_room ON room_files(room_code_hash, created_at DESC);
CREATE INDEX idx_room_files_expires ON room_files(expires_at);
```

## API Routes (Next.js)

### `POST /api/rooms`

Create a room. Returns room code (6-digit alphanumeric, same as pickup code).

**Request:** `{}`  
**Response:** `{ code: string, createdAt: string }`  
**Auth:** Site auth required.

### `GET /api/rooms/[code]`

Validate room exists. Returns room metadata.

**Response:** `{ code: string, fileCount: number, createdAt: string }`  
**Auth:** Site auth required. Room code validated via path param.

### `POST /api/rooms/[code]/join`

Validate room password (the 6-digit code is the password). On success returns a join token (valid for 5 minutes, used for WebSocket authentication).

**Request:** `{ code: string }`  
**Response:** `{ joinToken: string, expiresAt: string }`  
**Auth:** Site auth required. Room code must match.

### `GET /api/rooms/[code]/files`

List all files in a room. No pickup code needed — room members have access.

**Response:** `{ files: RoomFile[] }`  
**Auth:** Validate join token or WebSocket session.

### `GET /api/rooms/[code]/files/[fileId]/download`

Download a file from a room. No download limits enforced for rooms (by default unlimited).

**Auth:** Validate join token.

### `GET /api/rooms/[code]/files/[fileId]/preview`

Preview a text file from a room.

**Auth:** Validate join token.

### WebSocket endpoint

Handled by the `Room` Durable Object, not by Next.js route handlers.

## Durable Object: `Room`

Location: `src/server/room-do.ts`

```
class Room implements DurableObject {
  // state (stored in DO storage):
  //   codeHash, storagePrefix, createdAt
  //   webSockets: Map<WebSocket, { id, tag }>

  fetch(request) - handles WebSocket upgrade, returns 101
  webSocketMessage(ws, message) - handles client messages
  webSocketClose(ws, code, reason, wasClean) - client disconnect
  webSocketError(ws, error) - error handling
  alarm() - periodic idle check

  Client messages:
    { type: "ping" }               → { type: "pong" }
    { type: "upload", file }       → { type: "fileAdded", file }
    { type: "subscribe" }          → { type: "sync", files: [...] }
    { type: "delete", fileId }     → { type: "fileDeleted", fileId }
}
```

## Frontend Components

### Mode Switch

- **Location:** Page top-right (above/within the content area)
- **Component:** `<TransferModeSwitch />`
- Uses the same toggle design as the existing file/text mode switch (`.switch-track` / `.switch-thumb`)
- Labels: "快递柜" / "房间" (zh) or "Locker" / "Room" (en)
- State managed in `LockerApp` → conditionally renders `<LockerModeView />` or `<RoomModeView />`

### Room Mode View

- **Component:** `<RoomModeView />`
- Contains: Room create/join flow → Room file list view

### Room Create/Join

- **Component:** `<RoomGate />`
- If no active room, shows:
    - "创建房间" (Create Room) button → calls POST /api/rooms
    - "加入房间" (Join Room) → 6-digit code input (reuses `PickupCodeInput`) + "加入" button

### Room View (after joining)

- **Component:** `<RoomView />`
- Layout:
    1. **Top:** Upload block (file/text, same as locker upload panel but simpler)
    2. **Below:** File list with columns: File Name | Type | Upload Time | Remaining Count/Time
    3. Each row is clickable → download or text modal

### File Upload Block

- **Component:** `<RoomUploadBar />`
- Horizontal bar with:
    - Text input field + "上传文本" button
    - "选择文件" button (file picker)
    - Both upload via REST API, then broadcast via WebSocket

### File List

- **Component:** `<RoomFileList />`
- Table-like layout showing all room files
- Real-time updates via WebSocket `sync` messages
- Each row shows:
    - File name (clickable)
    - File type badge
    - Upload time (formatted)
    - Remaining downloads ("无限" or "3/10") and expiry time ("24h" or explicit date)

### Text File Modal

- **Component:** `<TextFileModal />`
- Reuses the existing `admin-modal` / `text-preview` styling patterns
- Shows: file name header, text content in `<pre>`, close button

### File Row Component

- **Component:** `<RoomFileItem />`
- Renders a single file row
- Clicking the row:
    - For text files → opens `<TextFileModal />`
    - For files → triggers download via REST API

## Wrangler Configuration

Add to `wrangler.jsonc`:

```jsonc
{
	"durable_objects": {
		"bindings": [
			{
				"name": "ROOM_DO",
				"class_name": "Room",
			},
		],
	},
	"migrations": [
		{
			"tag": "v1",
			"new_classes": ["Room"],
		},
	],
}
```

Note: The DO class must be exported from the worker entry point. Since opennext auto-generates the entry, we customize via `scripts/worker-entry.mjs`.

## Security Considerations

- Room passwords are 6-digit alphanumeric + hashed with HMAC-SHA256 + pepper (same as pickup codes)
- WebSocket connections authenticated via join token (short-lived, 5 min)
- Files uploaded to rooms are stored under `rooms/ROOM_CODE/` prefix in R2
- Room auto-destruction deletes all R2 objects and D1 records
- Site auth required to create/join rooms (same as existing locker)
